# Direct agent chat, assignments and chibi portraits

The user requested direct conversations with each agent, task assignment and visibility into actual work, plus chibi portraits resembling the supplied Grand Chase roster. They chose separate personal/project conversations. The existing native subscription, exact-image approval, Firefox, process ownership and JavaScript/JSX constraints remain in force.

## Delivered contracts

- Agent cards open Chat; the pencil retains inline profile editing. Conversations have fixed profile snapshots, a fixed project or personal context and server-owned native thread IDs. New chats use the current profile. Saved history remains readable when execution is unavailable.
- Chat sends a message; Assign task creates a tracked `agent_task` with a durable result and owned text artifacts. Tasks and Activity tabs show results, files, commands, tool calls, output, errors, elapsed/last-activity time and actual status. Active/queued roster captions use execution records; configuration alone never creates an executor.
- The existing single AI queue remains. Different conversations can queue; duplicate active turns in the same conversation are rejected. Cancelling/retrying operates on the scoped job, preserves the original user message and does not stop project services. Interrupted work requires explicit retry.
- Direct work can research through native web search, inspect a freshly bounded/secret-filtered project snapshot and write only inside its owned workspace. Native named filesystem permissions deny original project and credential paths. Connected-app writes, hooks and browser runtimes are disabled in these turns. No provider credentials are copied or an API billing fallback introduced. Website source changes retain their existing exact-image approval/implementation path. Its UI handoff keeps the chosen project or asks for one from a personal chat.
- Events have an additive indexed conversation column. The API scopes history, activity and downloads to the selected conversation. Older stores migrate under an immediate transaction. API owner pairing/CSRF checks still apply before the new router.
- Outputs are published only after a completed nonempty native result, client shutdown and a durable cancellation check. Response/file records commit together. Oversized responses fail explicitly. Text outputs are bounded and redacted; unsafe files, symlinks and credential-like content are excluded.
