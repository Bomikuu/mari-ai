# Dot coordination through local Codex

The owner approved a bounded local command and discoverable skill, reusing Mari’s existing queue, Elesis delegation, profile snapshots, worker permissions and approval workflow. No Dot-specific control API was found in the installed Codex protocol. The supported route is a dot starting a task on its connected computer, where that Codex task can use the installed local skill.

Official documentation: [Computers and apps](https://learn.chatgpt.com/docs/dots/computers-and-apps), [Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory), [Dot access and usage](https://learn.chatgpt.com/docs/dots#access). Connecting a computer is an owner-controlled native setting. No cloud Dot credentials are copied into Mari.

## Implementation

- `scripts/dot-handoff.js`: JSON CLI for health, registered projects, recent requests, submit, status, result and cancel. Uses the repository’s canonical default runtime independent of the caller’s cwd, or an explicit existing absolute runtime; a typo cannot create an empty runtime. Submissions arrive through stdin, limited to 32 KiB, with an explicit project ID or Personal `null`, a 6,000-character instruction limit, and no arbitrary command, permission or path fields.
- `server/dot-handoff.js`: prepares an existing Elesis team goal, commits it with a durable receipt in one SQLite transaction, deduplicates stable IDs and rejects changed replay content. Rechecks worker/coordinator/project state after asynchronous preparation and bounds simultaneous handoff goals to three. Handoff events appear in the existing activity stream and the normal agent/team workspace.
- Worker readiness requires a fresh matching lease, Linux PID/start/boot/process-group identity and a normal worker’s explicit `jobTypes: null` capability. Temporary restricted workers are rejected. Worker loss remains separate from the saved team’s last reported execution. Live action/command fields require the current worker and working agent; historical actions are labeled separately.
- Status returns up to 60 scoped events with a resumable cursor. Result returns the completed synthesis only when the synthesis reply and job are completed, plus separately labeled completed specialist results and owned artifact metadata. Text is redacted and bounded; full saved work remains in Mari. No unrelated chat, arbitrary file, raw event payload, credential file or provider-auth record is returned.
- Cancellation resolves the receipt’s exact team, checks origin and scope, and calls existing team cancellation in the same transaction. It has no service-control path and cannot cancel an unrelated team ID. Repeated cancellation is harmless. The connector does not automatically retry failed work or consume unrelated queued jobs through a temporary worker.
- `skills/mari-handoff` is installed in the user’s Codex skills directory. Its instructions cover fixed context, minimum necessary input, safe stdin invocation, stable IDs, observation, failure boundaries and the distinction between a local source label and cloud authentication. `scripts/install-dot-skill.js` is idempotent for identical content and refuses to replace a different existing skill.

This is a local OS-owner interface, not an untrusted network API. Any process already running as this user can access the local runtime; the handoff source label is not cryptographic proof of a particular dot. No new port, tunnel, copied login credential or API-billed provider is introduced. Native agent turns retain the existing subscription authentication, separate owned workspaces, bounded project source snapshots and captured knowledge context. Website editing still requires exact-image owner approval and explicit implementation. No frontend layout was changed for this connector.
